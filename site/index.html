What It Does

The Layaway Jar is a single-saver covenant built on Bitcoin Cash as an XO template. The saver commits satoshis toward a fixed merchant destination and a fixed savings target, with the covenant's authoritative balance tracked directly by its UTXO satoshi value. Once the target is satisfied, funds can be released to the merchant with any excess returned to the saver; alternatively, the saver can unconditionally refund the balance at any time with zero middleman or admin keys.

Action Covenant Rule
createJar Creates the P2SH32 jar output with an initial balance, fixed merchant script, and target amount.
deposit Output 0 must have the same covenant bytecode and a strictly larger value. Target, merchant, saver, and jar key stay fixed.
release Output 0 must pay the merchant script exactly the target, and the jar input must already hold at least the target. Extra value is returned to the saver by output 1.
refund Output 0 must pay the saver script, and at most 1,000 satoshis may be taken as network transaction fee.

Every spending path requires a valid Schnorr signature from the saver's key. There is no third exit and no admin backdoor.

Negative Test: Refusal Below Target

To prove enforcement, an invalid release transaction was forged where a jar holding only 2,000 sats attempted to release 10,000 sats to the merchant. Evaluated against the Bitcoin Cash Script VM via libauth: 

COVENANT_REFUSED_AS_EXPECTED: VM rejected input 0: Program failed an OP_VERIFY operation.

The covenant rejected the input because the authoritative UTXO value was below target. The transaction failed script evaluation locally and was never broadcast.

How to Reproduce

Reproduce using Node.js / TypeScript against the template with fresh Chipnet UTXOs: 

git clone https://github.com/matrixneoaiagent/layaway-jar && cd layaway-jar
npm install
npm run typecheck && npm test          # 16 tests; engine integration is opt-in

# Use a Chipnet test wallet only — never a funded mainnet wallet:
export XO_WALLET=/path/to/chipnet-wallet.json
export XO_DB_PATH=/tmp/opencode/xo_bounty   # optional; omit to sync a fresh .xo-data

# One command runs create → deposit → release → create → refund:
bash scripts/run-final-chipnet.sh

# Each step prints VM_OK, the txid and the merchant/saver split.
# Individual commands: npm run create | deposit | release | refund
# Invitations go to artifacts/ and can be pasted into blaze.xo.cash.
